# ProxyDesk — Портативный менеджер прокси, локального шлюза и пользовательского DNS

**ProxyDesk** — компактное портативное приложение на Go со встроенным веб-интерфейсом (`go:embed`) и базой SQLite (`modernc.org/sqlite`, сборка с `CGO_ENABLED=0`) для Windows 10/11 x64 (с кроссплатформенным ядром для Linux и macOS).

Программа объединяет сбор кандидатов из публичных и локальных источников, поэтапную сетевую проверку (`HTTP`, `HTTP CONNECT`, `SOCKS5`), исторический рейтинг с эвристикой полноты наблюдений, пулы с гистерезисом, локальный прокси-шлюз (`HTTP CONNECT` и `SOCKS5`) и локальный DNS-прокси (`UDP`/`TCP`/`DoH`/`DoT`) со структурированным объяснением каждого решения (`Decision Trace`).

## 1. Реализованные возможности (Инкременты A → H)

- **Инкремент A (Основа и импорт)**:
  - Конфигурация с версионированием (`version: 1`) и строгой валидацией бюджетов ресурсов.
  - Флаги `--portable` (папка `data/` рядом с исполняемым файлом, а не в текущем рабочем каталоге), `--data-dir` (приоритет над `--portable`), `--no-open-browser` и `--listen`.
  - Защита от конфликта двух запусков на одной базе (`instance.lock` + проверка `/api/v1/health` без принудительного завершения чужих процессов).
  - Защищенный loopback API (`127.0.0.1`), валидация `Host`/`Origin`/`Sec-Fetch-Site` против DNS rebinding и CSRF, сессионный токен `X-ProxyDesk-Token`.
  - Безопасная дедупликация (`protocol://host:port#sha256(user:pass)`): прокси с разными паролями не смешиваются, а сами пароли хранятся только в оперативной памяти сессии и не попадают в БД, логи или диагностические архивы.
- **Инкремент B (Источники и планировщик)**:
  - Поддержка источников `URL`, локальных файлов (`TXT`, `CSV`, `JSON`) и статического `HTML` (без выполнения JS).
  - Поддержка `ETag` / `Last-Modified` и корректная обработка `HTTP 304 Not Modified`.
  - Защита от SSRF на этапе фактического сетевого соединения (`net.Dialer.Control`), лимит редиректов (`<= 3`) и размера ответа (`10 МБ`).
  - Управляемый планировщик с экспоненциальным backoff и детерминированным jitter, защита от повторного параллельного запуска одного источника.
- **Инкремент C (Checker)**:
  - Поэтапная проверка `HTTP` forward-прокси, `HTTP CONNECT` для HTTPS и `SOCKS5 CONNECT` (с передачей домена на SOCKS5-сервер через `ATYP=0x03` без локального DNS-резолвинга).
  - Полная проверка TLS-сертификатов целевых HTTPS-хостов (никаких `InsecureSkipVerify` или MITM CA).
  - Раздельный замер `connect_ms`, `handshake_ms`, `ttfb_ms`, `total_ms` и извлечение `exit_ip`.
  - Различение исходов `success`, `failure`, `inconclusive` и `cancelled`: отмена задачи или недоступность контрольных целей не штрафует пул прокси.
- **Инкремент D (История, рейтинг и пулы)**:
  - Агрегация проверок по циклам (несколько контрольных целей внутри одного прогона считаются одним циклом наблюдения).
  - Рейтинг `0–100` и отдельная эвристика полноты наблюдений (`confidence` `0.0–1.0`, учитывающая число циклов и временной охват).
  - Машина состояний `unknown → checking → healthy / degraded / quarantined` с экспоненциальным cooldown и пробным восстановлением.
  - Пулы (`manual`, `reliable`, `fast`, `protocol`, `custom`) и стратегии (`fixed`, `failover`, `best_score`, `round_robin`, `weighted`) с гистерезисом и проверкой актуальности `CapabilityState` (`unknown`, `confirmed`, `unsupported`, `transient_error`, `stale`).
- **Инкремент E (Локальный шлюз)**:
  - Локальный `HTTP/CONNECT` и `SOCKS5` шлюз на loopback без MITM и без расшифровки HTTPS.
  - Маршруты `proxy`, `pool`, `block` и явно разрешаемый `direct`.
  - Переключение на резервный прокси (failover) строго до подтверждения туннеля без повторной отправки прикладных данных и без утечки заголовка `Proxy-Authorization`.
- **Инкремент F и G (DNS в пользовательском режиме и связь с маршрутами)**:
  - Локальный DNS-прокси (`127.0.0.1:15353`) с поддержкой `UDP`, `TCP`, `DoT` и `DoH` (с bootstrap IP и проверкой TLS по имени эндпоинта).
  - Автоматический повтор по TCP при усеченном UDP-ответе (`TC=1`), корректная обработка `NXDOMAIN` (не считается транспортной ошибкой) и запрет утечки внутренних доменов (`.local`, `.internal`, `.corp`, `.lan`) в публичный fallback.
  - Изолированные пространства имен TTL-кэша по DNS-политикам (`INV-06`).
  - Явное разделение режимов `Remote DNS` (имя разрешает upstream-прокси) и `Managed DNS` (разрешение через выбранную DNS-группу с сохранением `Host`/TLS `SNI`).
- **Инкремент H (Полировка, бэкап и диагностика)**:
  - Экспорт списков прокси (`TXT`/`JSON`), экспорт конфигурации без секретов, безопасный бэкап SQLite (`VACUUM INTO`) с проверкой версии схемы и выгрузка очищенного диагностического ZIP-архива.

## 2. Воспроизводимые команды сборки и запуска

### Сборка для Windows 10/11 x64 (`CGO_ENABLED=0`)

```bash
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o dist/proxydesk-windows-amd64.exe ./cmd/proxydesk
```

### Сборка для текущей ОС (Linux / macOS)

```bash
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o dist/proxydesk ./cmd/proxydesk
```

### Запуск в портативном режиме

```bash
./proxydesk.exe --portable
```

Дополнительные флаги командной строки:
- `--portable` — хранить конфигурацию, базу `proxydesk.db` и логи в папке `data/` рядом с `proxydesk.exe`;
- `--data-dir <путь>` — явно задать каталог хранения данных (имеет приоритет над `--portable`);
- `--no-open-browser` — не открывать браузер автоматически при запуске;
- `--listen 127.0.0.1:18443` — изменить локальный адрес веб-интерфейса и API.

### Проверка тестов и статического анализа

```bash
go vet ./...
go test -v ./...
go test -race ./...
go test -fuzz=FuzzNormalizeProxyLine -fuzztime=10s ./internal/parsers
node --test web/test_ui.mjs
```

## 3. Известные ограничения текущего выпуска

1. **Только пользовательский режим (User Mode)**: программа не меняет системный DNS Windows, не прописывает системный прокси в реестр `WinINET`, не устанавливает драйверы `Wintun`/`WinDivert` и не перехватывает трафик других процессов автоматически. Приложения подключаются к локальному шлюзу ProxyDesk (`127.0.0.1:18080` или `127.0.0.1:18081`) или локальному DNS (`127.0.0.1:15353`) явно.
2. **Семантика TCP Failover**: при отказе активного прокси новые соединения автоматически переводятся на резервный узел из пула, однако уже открытые TCP/TLS-туннели при обрыве связи с прокси должны быть переоткрыты клиентским приложением.
3. **Хранение паролей прокси**: в соответствии с политикой безопасности пароли авторизованных прокси хранятся только в оперативной памяти процесса до его завершения и не записываются на диск в открытом виде.
4. **Публичные прокси**: бесплатные прокси из открытых списков являются недоверенной инфраструктурой — никогда не передавайте через них незашифрованный HTTP-трафик, пароли или личные данные.
