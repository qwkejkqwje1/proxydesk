# Предложение по системному этапу для Windows 10/11 x64 (docs/system-stage-proposal.md)

Документ подготовлен в соответствии с разделом 11 ТЗ («Что не входит в этот пакет») для проектирования следующего привилегированного этапа **ProxyDesk** на Windows 10/11 x64.

## 1. Разграничение режимов и текущие гарантии (Инвариант INV-09)

В текущем выпуске (Инкременты A–H) ProxyDesk работает исключительно в непривилегированном пользовательском режиме:
- не изменяет системный DNS Windows;
- не изменяет настройки `WinINET` / `PAC` в реестре;
- не устанавливает драйверы (`Wintun`, `WinDivert`) и системные службы Windows;
- не перехватывает трафик за пределами локальных сокетов `127.0.0.1`.

## 2. Сравнение механизмов системного перехвата на Windows 10/11 x64

| Подход / Компонент | Решаемая задача | Лицензия и поставка | Требуемые привилегии и зависимости | Ограничения |
| :--- | :--- | :--- | :--- | :--- |
| **WinINET / системный PAC (`HKCU\...\Internet Settings`)** | Автонастройка браузеров и приложений, соблюдающих системный прокси Windows. | Встроенный API Windows (`wininet.dll`, `InternetSetOptionW`). | Права обычного пользователя (профиль `HKCU`). | Игнорируется консольными утилитами, играми, приложениями со своим сетевым стеком и UDP/QUIC-трафиком. Нельзя называть режимом «весь трафик ПК». |
| **Wintun (`wintun.dll`) + userspace TCP/IP стек (`gVisor netstack` / `sing-tun`)** | Виртуальный L3 TUN-адаптер для перехвата IPv4/IPv6 трафика всей системы. | Драйвер Wintun: `GPL-2.0` (распространяется как подписанный Microsoft WHQL бинарник `wintun.dll`); `gVisor`: `Apache-2.0`. | Администратор (`SeLoadDriverPrivilege`), отдельный сервис/helper `proxydesk-helper.exe`. | Сам по себе пакет в TUN не несет `PID` и пути процесса; для привязки пакета к процессу требуется дополнительная корреляция через таблицы `GetExtendedTcpTable` / `GetExtendedUdpTable` или WFP. |
| **Windows Filtering Platform (WFP, `fwpuclnt.dll`)** | Строгий Kill Switch на уровне ОС, защита от утечек мимо TUN и фильтрация по процессу (`FWPM_CONDITION_ALE_APP_ID`). | Системный API Windows (`fwpuclnt.dll`). | Администратор (сессия `FwpmEngineOpen0` в `proxydesk-helper.exe`). | WFP удобен для блокировки (Kill Switch) и разметки/редиректа сокетов на этапе `ALE_AUTH_CONNECT`, но для прозрачного заворачивания L3-пакетов в SOCKS5/HTTP CONNECT требует связки с локальным прокси или Wintun. |
| **WinDivert (`WinDivert.dll` + `WinDivert64.sys`)** | Перехват и инжекция пакетов и сопоставление сетевых потоков с `PID` процессов. | Двойная лицензия `LGPL-3.0` / коммерческая. | Администратор, загрузка подписанного ядерного драйвера `WinDivert64.sys`. | Некоторыми антивирусами и античитами (Vanguard, BattlEye, EAC) блокируется или помечается как сетевой перехватчик. |

## 3. Рекомендуемая архитектура системного этапа

1. **Двухпроцессная схема с минимальным IPC**:
   - Непривилегированный `proxydesk.exe` (UI + база + чекер + шлюз) общается с привилегированным сервисом `proxydesk-helper.exe` через именованный канал Windows (`\\.\pipe\ProxyDeskHelper`) с проверкой ACL (доступ только SID владельца сессии и `SYSTEM`) и HMAC-подписью команд.
2. **Защита от петель перехвата (Loop Prevention)**:
   - В режиме Wintun + WFP все исходящие соединения самого процесса `proxydesk.exe` (по `FWPM_CONDITION_ALE_APP_ID`) и адреса активных upstream-прокси/DNS-резолверов добавляются в список bypass-исключений до поднятия маршрута по умолчанию.
3. **План Snapshot, Rollback и аварийного восстановления (Crash Recovery)**:
   - До любого изменения реестра `WinINET`, маршрутов, DNS адаптера или правил WFP записывается атомарный журнал `data/system_snapshot.json` с контрольной суммой и идентификатором сессии.
   - Для правил WFP используется флаг `FWPM_SESSION_FLAG_DYNAMIC` для временного режима (ОС сама удаляет фильтры при падении процесса `proxydesk-helper.exe`) либо отдельный persistent sublayer с кнопкой «Остановить и восстановить сеть» и автоматическим откатом при следующем запуске после BSOD/отключения питания.
   - Если после старта программы пользователь или сторонний VPN изменил системные настройки, при штатном выходе ProxyDesk сверяет текущие значения с записанными им параметрами и не затирает внешние изменения.

## 4. Обязательные тесты на реальной ОС Windows 10/11 x64 перед включением системного этапа

1. **Тест WinINET/PAC Rollback**: включение системного прокси → принудительное завершение процесса (`taskkill /F /PID`) → повторный запуск → проверка автоматического восстановления исходных параметров `ProxyEnable` и `ProxyServer`.
2. **Тест отсутствия петли маршрутизации**: включение TUN-режима → запуск массовой проверки 100 прокси → подтверждение, что трафик чекера не заворачивается внутрь собственного TUN-интерфейса.
3. **Тест Kill Switch (WFP)**: включение строгого режима → искусственный обрыв всех прокси из пула → проверка, что `curl.exe`, браузер и `nslookup.exe` не выходят в интернет напрямую с реального IP хоста.
4. **Тест совместимости с корпоративными VPN**: запуск ProxyDesk при активном WireGuard / OpenVPN клиенте → проверка сохранения таблиц маршрутизации и DNS-суффиксов VPN.
